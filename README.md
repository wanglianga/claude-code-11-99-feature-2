# 避难所入住与返所工作台

供**接待员、楼层值班员、床位管理员**共同操作的床位管理工作台。核心目标：让暂时外出的家庭仍有床可回，同时继续接待新到家庭——分房、现场入住、暂离、返所、核实退住各有明确结果，而不是只维护一个全所剩余人数。

纯浏览器前端：React + TypeScript + IndexedDB + WebWorker，计算与持久化全部在本地完成，不依赖后端，不使用真实居民资料（内置虚构家庭与房间）。

## 领域规则实现要点

- **家庭不可拆分**：整组家庭只进一个房间；房间容量、共房同意、无障碍要求同时满足才可分配。
- **草稿不占床**：分房草稿不产生床位占用；**现场入住确认后**才计入实际在场人数（确认经由本地模拟适配器异步完成，确认中床位单独预占、不计在场）。
- **暂离 ≠ 退住**：暂离后实际在场人数减少，但住宿关系未结束，返所承诺继续占床（保护中），绝不因人数减少把床让给别人。
- **两条床位保护路径**（都必须兑现返所权）：
  - **原房原床保留**：回程明确，但保护床位期间不参与分配（可能空置紧缺房间）；
  - **容量保护（返所换房）**：家庭须事先同意换房；释放原房，在另一房间保护同等床位作为返所安排，可腾出稀缺房型；返所时回执提示**须向家庭说明新房**。
- **每次变更重核全部承诺**：新分房、返所、延期、关房等都在事务内重新核验房间资格与所有有效返所承诺能否按家庭整组兑现；失效草稿保留输入并说明冲突。
- **到期未归只产生联系核实任务**，不自动认定退住；**退住须楼层值班员核实**（异步确认），核实后结束返所权、释放床位。
- **已入住家庭不得被自动搬走**：关房时如房内仍有在场家庭或「原房原床」承诺则拒绝；「容量保护」承诺可整组迁移到他房，无法迁移则拒绝关闭。
- **多标签并发**：同一站点（origin）多标签共享 IndexedDB；所有写命令在单个 IndexedDB readwrite 事务内「读取→校验→写回」，跨标签天然串行，后到命令在事务重核中得到明确冲突结果。
- **幂等**：每条命令携带 commandId，重复提交只生效一次并开具「重复回执」。

## 本地启动

要求 Node 18+（推荐 22）。

```bash
npm install        # 安装依赖
npm run dev        # 开发模式：http://localhost:5173
```

其他命令：

```bash
npm run test       # 运行领域引擎单元测试（vitest）
npm run build      # TypeScript 检查 + 生产构建到 dist/
npm run preview    # 预览生产构建：http://localhost:4173
```

## Docker 一键启动

```bash
docker compose up --build
# 打开 http://localhost:8080
```

（等价地：`docker build -t shelter-bed-workbench . && docker run -p 8080:80 shelter-bed-workbench`。镜像为多阶段构建：Node 构建静态产物，Nginx 托管，无需任何后端服务。）

## 演示账号（角色）

无需账号密码。页面右上角下拉即可切换三个演示角色，权限由引擎在事务内再次校验：

| 角色 | 权限 |
| --- | --- |
| 接待员 | 登记家庭、草稿分房、提交入住确认、暂离登记、确认返所 |
| 楼层值班员 | 核实退住、承诺延期、联系任务备注 |
| 床位管理员 | 临时关闭 / 重新开放房间 |

任何角色都可推进演示时间、查看核对面板与回执流。

## 演示脚本（对应题目要求的验证场景）

初始场景即题目示例：A 房 6 床（无障碍）、B 房 6 床（普通）；王芳与女儿 2 人在住 B；李强一家 4 人在住 A（不需无障碍、已同意返所换房）；赵敏一家 3 人（需无障碍）待安置。演示时间 15:00。

1. **两条保护路径对比**
   - 李强一家「暂离登记」选**原房原床保留**（至 18:00）→ A 房在场 0、保护中 4、可分配 2；赵敏一家仍无法安置，待安置面板给出原因（A 可分配 2<3；B 无无障碍）。
   - 右上角「重置演示数据」后改选**容量保护 → 保护于 B 房** → A 释放 6 床，B 在场 2+保护 4；赵敏一家可草稿分房到 A 并入住。
2. **四人家庭按时返所**：李强一家「确认返所」→ 容量保护路径下安排到 B 房，回执注明「返所换房说明：原 A 房 → 现 B 房，请向返所家庭说明新房」；原房保留路径则回到 A 房原床。
3. **重复暂离回执**：暂离成功后，该家庭行出现「模拟重复提交暂离回执」按钮（以相同 commandId 重发）→ 回执流出现「重复提交已幂等忽略」，承诺仍只有一条。
4. **保护房间临时关闭**（床位管理员）：B 房有在场家庭时关闭被拒（已入住家庭不得被自动搬走）；王芳退住后关闭 B，可把李强的容量保护整组迁移到 A；若 A 剩余不足 4 床则拒绝关闭并说明「无法整组兑现」。
5. **两标签同时分房**：开两个浏览器标签（同一地址）。李强暂离（容量保护）且赵敏入住 A 后，A 仅剩 3 床：标签 1 为吴磊一家（3 人）创建草稿并提交入住确认；标签 2 为另一家庭创建草稿——草稿失效并显示冲突原因（可分配 0 床<3 人），输入保留可重试。
6. **中途刷新**：任何操作中途刷新页面（含入住确认提交后 1 秒内），状态从 IndexedDB 恢复，未完成的异步确认由 worker 启动时补结算。
7. **承诺到期未归**：暂离至 18:00 后用「+1小时」把演示时间推过 18:00 → 自动生成联系核实任务（不自动退住、床位继续保护）；值班员可「延期1小时」「核实退住」或添加备注。
8. **全所核对**：右侧「全所核对」面板实时校验：家庭唯一位置、房间容量不被突破、返所承诺可整组兑现、实际在场人数两种口径一致、已入住家庭未被自动搬动。

## 架构与目录

```
src/
  engine/           # 纯函数领域引擎（UI 与 Worker 共用同一口径）
    types.ts        # 领域模型与命令定义
    seed.ts         # 虚构演示数据（对应题目示例）
    engine.ts       # 命令处理、资格核验、承诺核验、幂等、不变量
    format.ts       # 时间格式化
  worker/           # WebWorker：所有写操作在此串行落库
    store.ts        # IndexedDB 单记录事务（读取→校验→写回）
    worker.ts       # 命令分发 + 本地模拟适配器（异步确认定时结算）
  ui/               # React 工作台
    client.ts       # Worker 客户端 + BroadcastChannel 多标签同步
    App.tsx         # 主界面（角色、时钟、面板装配）
    components.tsx  # 房间看板/家庭列表/暂离与草稿面板/任务/回执/核对
  test/
    engine.test.ts  # 14 个领域引擎测试
```

关键设计：

- **单记录事务状态**：整份状态存于 IndexedDB 单条记录，命令在事务内完成「读→引擎校验→写回」，多标签并发由 IndexedDB 序列化，杜绝脏写。
- **异步确认（本地模拟适配器）**：入住确认、退住核实先落库为待结算单（带应结算真实时间戳），worker 定时清扫结算；刷新后任一标签的 worker 启动即补结算。
- **虚拟时钟**：业务时间（如承诺到期）使用可推进的演示时钟；异步确认的模拟网络时延使用真实时钟，两者互不干扰。
- **数据安全**：全部数据仅存于本浏览器 IndexedDB，清除站点数据即可彻底删除；无任何网络请求与后端依赖。
